Task 3: Ruling: the protection switch is a control route, not a Tauri command — PUT /local/protection writes the `local` section of the sidecar-owned config.json (one writer), answers 202, prints a `{"event":"restart"}` line and shuts the engine down; whoever spawned it (the Tauri shell, or scripts/dev.mjs) respawns it, reading `local` from config.json for KV_PROTECTED/KV_ADMIN_ADDRESS. The shell keeps a read-only LocalProtection::load of that section; the plan's AppConfig/config_write commands are not added. Why: one config file with one writer; the switch works identically in the browser (e2e) and under the shell; spec §5.6 puts config.json in the data dir. Cost if wrong: an implicit supervisor protocol — a supervisor that misses the restart line leaves the engine down until relaunch (the host shows "The engine stopped" with the code).
Task 3: Ruling: the sidecar authenticates its own engine calls (vault list/create/rename/delete, Workflows drive) with the user's token when protected — the plan omitted it and every management call would 401 the first time protection went on. Cost if wrong: a token minted per call batch; cached by the identity module.
